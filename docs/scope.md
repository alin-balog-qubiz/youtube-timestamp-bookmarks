# YouTube Timestamp Bookmarks — product scope

## Purpose

A personal Chrome extension for quickly saving moments in YouTube videos and returning to them. This is an open-source learning project maintained by its author and coding agents. The first version favors a small, usable workflow over a general bookmarking platform.

## First-version use cases

1. On a standard `youtube.com/watch` page, click a small `+` button among the player controls to save the current whole-second position instantly, without pausing or prompting. Brief feedback near the button says **Saved** or **Already saved**. The same video and second identify one bookmark; saving it again leaves the existing bookmark unchanged.
2. See saved moments as clickable colored markers on that video's progress bar. Hovering reveals time and optional name; clicking seeks within the player without taking over normal progress-bar controls. Nearby markers may overlap; the popup list remains the reliable way to select them.
3. Open the extension popup on **This video** for a supported watch page, or **All videos** elsewhere. Outside YouTube, show a notice but keep browsing and Settings available. All videos lists saved titles (falling back to video ID) and bookmark counts, ordered by most recent bookmark creation date. Expand a video to reveal chronological timestamps. Clicking a title opens its watch page in a new tab; clicking a timestamp seeks if that video is active, otherwise opens a new tab at that time. Filter by case-insensitive partial video title only, preserving list order; no ID/name matching, typo tolerance, or relevance ranking. Visiting a video may refresh its stored title.
4. All videos is a launcher with one management action: delete all bookmarks for a selected video, confirmed with video identity and bookmark count. Individual editing, deletion, and link copying belong only to This video. There, show formatted time, optional name, and color; seek, copy a timestamped URL, edit, delete one, or delete all for that video. Confirm single and bulk deletion; a video with no bookmarks disappears from All videos. The edit dialog saves name, color, and timestamp together or cancels without changes. Fine-tune with −5/−1/+1/+5-second buttons within zero through the floored active-player duration. Unknown duration disables adjustment, not name/color editing. Moving onto an existing bookmark is rejected without changing either; a successful move preserves creation date. Keep All videos and Settings reachable, and show This video navigation only in supported active-video context.
5. In Settings, immediately persist show/hide player markers without disabling quick add or popup browsing. Choose a global default marker color with the browser's native color picker; each bookmark may choose a custom color with the same kind of picker or return to **Use default**. Changing the global default affects bookmarks without an override. Report persistence failures rather than claiming success.
6. Export a readable JSON backup containing all bookmarks and settings. In Settings, import proceeds through file selection, **Merge / Replace**, effect preview, and explicit confirmation. Merge adds non-duplicates and keeps existing bookmarks/current settings; Replace replaces bookmarks and settings with destructive confirmation. Preview additions/skipped duplicates for Merge and current data being replaced, incoming totals, and settings changes for Replace. Reject invalid files without changing stored data; cancellation also leaves data unchanged.
7. Empty states say nothing is saved yet and point to the player `+` button on a watch page or to YouTube elsewhere. A separate, extension-owned Guide page remains planned, covering quick add, markers/colors, popup management, and JSON backup/restore. Both Guide and Welcome are deferred from the current popup work; add Guide links only once its destination exists.

## Bookmark information

A bookmark belongs to a YouTube video ID and a whole-second position; together they identify it. It has an optional name, an optional color override, and a creation date; the video also has a stored title for display. Unnamed bookmarks display their formatted time. Timestamp adjustment moves that identity within the same video, preserves creation date, and rejects collisions. The storage contract and precise field shapes belong in the relevant implementation spec and code, not in this document.

## Interface expectations

Use actual shadcn/ui components where helpful in a compact, scrollable popup (roughly 380–420 px wide): restrained layout, system light/dark theme, video title/count on All videos, and time/name/color on bookmark rows. Keep All videos and Settings reachable from a persistent header, with This video available on supported watch pages. All videos expands into playback-launching timestamps; edit/copy/single-delete row menus belong to This video. Use a small edit dialog with explicit Save/Cancel. Prioritize basic features and clear loading/empty/error states over visual polish. The player control should fit YouTube, have an accessible label and tooltip, and not cover the video; feedback stays beside it. The eventual Guide is a separate page, not a popup view.

## Boundaries and later ideas

First-version playback integration covers standard YouTube watch pages. Shorts, live streams, embeds, and `youtu.be` entry points are outside that integration. Use local extension storage via `wxt/utils/storage`; no account or cross-device sync. All videos has a partial-title filter; advanced sorting, fuzzy/typo-tolerant search, ID/bookmark-name search, and direct timestamp entry are deferred. No tags, playlists, thumbnail previews, keyboard shortcuts, manual theme toggle, timestamp precision mode, undo, or popup quick-add action. These are possible later ideas, not commitments. Welcome and Guide are deferred from the current popup slice.

## Project architecture

- Separate domain models, bookmark/storage logic, host-website messaging adapters, and thin WXT entrypoints. Popup, player markers, and backup features must use the same persisted model rather than creating independent stores.
- YouTube page integration has one thin host-level content entrypoint and one shared player lifecycle. Quick add and player-message handling consume the same navigation/media checks; keep feature UI separate from shared player operations. Popup-side active-tab discovery combines browser-tab classification with a content-side active-video snapshot. Separate execution contexts exchange typed messages rather than share live JavaScript state.
- Store each video and its bookmarks together as one authoritative video record. Derive video lists and bookmark counts from those records rather than maintaining separate indexes or counts.
- Route bookmark mutations through the background worker. Serialize mutations for the same video so concurrent read-modify-write operations cannot overwrite each other's changes; a failed operation must not block subsequent ones.
- Use typed request/response messages with explicit success or failure results. Request validation returns a failure value; storage failures must also become failure responses, not successful feedback.
- Follow [coding conventions](agents/coding-style.md) for operation names, file ordering, helper placement, and execution-context terminology. Exact TypeScript fields, storage-key versions, and private implementation names belong in code.
