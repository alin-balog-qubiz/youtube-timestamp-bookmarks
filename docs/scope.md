# YouTube Bookmarks — product scope

## Purpose

A personal Chrome extension for quickly saving moments in YouTube videos and returning to them. This is an open-source learning project maintained by its author and coding agents. The first version favors a small, usable workflow over a general bookmarking platform.

## First-version use cases

1. On a standard `youtube.com/watch` page, click a small `+` button among the player controls to save the current whole-second position instantly, without pausing or prompting. Brief feedback near the button says **Saved** or **Already saved**. The same video and second identify one bookmark; saving it again leaves the existing bookmark unchanged.
2. See saved moments as small clickable colored markers centered on that video's progress bar. Hovering or keyboard focus reveals time and optional name, separated by a space without an em dash, in a rounded translucent dark tooltip styled like YouTube's controls tooltips, not a permanent label; clicking seeks within the player without taking over normal progress-bar controls. Nearby markers may overlap; the popup list remains the reliable way to select them.
3. Open the extension popup on **This video** for a supported watch page, or **All videos** elsewhere. Outside YouTube, keep browsing and Settings available without an informational banner. All videos lists saved titles (falling back to video ID) and bookmark counts, ordered by most recent bookmark creation date. Clicking a group header/title expands chronological timestamps; a separate **Go to video** action opens its watch page in a new tab. Clicking a bookmark seeks if that video is active, otherwise opens a new tab at that time. Filter by case-insensitive partial video title only, preserving list order; no ID/name matching, typo tolerance, or relevance ranking. Visiting a video may refresh its stored title.
4. All videos is a launcher with one management action: **Delete video**, which deletes that video's saved bookmarks after confirmation with video identity and bookmark count, not the YouTube source. Individual editing, deletion, and link copying belong only to This video. There, show formatted time, optional name (or **Unnamed bookmark**), and color; seek, copy a timestamped URL, edit, or delete one with confirmation. Video-level deletion lives only in All videos. A video with no bookmarks disappears from All videos. The edit dialog saves name, color, and timestamp together or cancels without changes. Fine-tune with −5/−1/+1/+5-second buttons within zero through the floored active-player duration. Unknown duration disables adjustment, not name/color editing. Moving onto an existing bookmark is rejected without changing either; a successful move preserves creation date. Keep All videos and Settings reachable, and show This video navigation only in supported active-video context.
5. In Settings, immediately persist show/hide player markers without disabling quick add or popup browsing. Choose a global default marker color from theme-aware **Accent / Gray / Ink** presets or a fixed **Custom** color using the browser's native picker. Bookmarks may override with the same choices or return to **Use default** inheritance. Changing the global default affects bookmarks without an override. Persist **Light / Dark / System** appearance, defaulting to System and following OS changes while selected. Report persistence failures rather than claiming success.
6. Transfer only videos and bookmarks in readable JSON; never settings, theme, marker visibility, or the global default color. In Settings, Export opens a video-selection modal with Select all, individual selection, selected totals, and an optional filename; its final Export action confirms the download. Import selects a file, then presents video selection, Merge / Replace, accepted totals, inspectable skips/reasons, and the operation's effect before a final action. Merge adds missing video/second identities, keeps existing titles/bookmark metadata, and shows informational differing-field conflicts separately from identical duplicates; disable a no-op Merge. Replace library installs only accepted selected data as the whole library, deleting all absent/deselected current videos; one clearly destructive final action, no second confirmation dialog. Settings remain untouched in both modes. Known-format invalid records may be skipped after disclosure; malformed/unsupported file envelopes block import. Empty/all-invalid imports and empty selections cannot clear the library. Cancellation/failure leaves stored data unchanged. Preserve explicit bookmark colors and destination-default inheritance. Launch schema 1 has no prelaunch backup compatibility. See the approved, not-yet-implemented [rewrite spec](../.scratch/import-export-rewrite/spec.md).
7. Empty states say nothing is saved yet and point to the player `+` button on a watch page or to YouTube elsewhere. A separate, extension-owned Guide page remains planned, covering quick add, markers/colors, popup management, and JSON backup/restore. Both Guide and Welcome are deferred from the current popup work; add Guide links only once its destination exists.

If active-tab context cannot be read, show a concise recovery notice: **Having trouble reading this tab’s context. Try opening YouTube.** YouTube is a link opening a new tab. Keep All videos and Settings available and This video unavailable until a supported context is known; the recovery link does not claim that context lookup has succeeded.

## Privacy disclosure and consent

Before accessing video, bookmark, or preference data, the popup presents a one-time privacy disclosure describing the information handled, local extension storage, and user-initiated JSON transfers. Consent requires an unchecked-by-default checkbox and an explicit **Agree and continue** action. Closing the popup without agreeing leaves popup data views and YouTube integration disabled. The content script reads only the stored consent decision until consent is granted; after grant, it may read the supported video context and use the existing bookmark workflow. Link the full policy from the in-product disclosure and publish `PRIVACY.md` in the Chrome Web Store privacy-policy field. This required disclosure is not a general Welcome or Guide page.


## Bookmark information

A bookmark belongs to a YouTube video ID and a whole-second position; together they identify it. It has an optional name, an optional color-choice override, and a creation date; the video also has a stored title for display. Unnamed bookmarks display their formatted time and **Unnamed bookmark** without persisting that fallback as a name. Timestamp adjustment moves that identity within the same video, preserves creation date, and rejects collisions. The storage contract and precise field shapes belong in the relevant implementation spec and code, not in this document.

## Interface expectations

Use the approved [design system](../.scratch/design-system/spec.md), implemented as native React TSX components without Radix UI, each in its own file with barrel exports, in a **560 px-wide popup up to 600 px tall**, respecting Chromium's native toolbar-popup limit and scrolling content rather than clipping it. The supplied quieter reference replaces the POC's UI; use restrained functional icons, **YouTube Bookmarks** text branding, off-white, readable text, separate danger styling, accessible interactions, and preserved real-operation safeguards. Keep a persistent header, All videos and Settings reachable, and This video available on supported watch pages. All videos expands into playback-launching timestamps; edit/copy/single-delete menus belong to This video. Editor and import workflows use bounded dialogs with explicit commit/cancel actions. Support light/dark/System themes and installed typography without remote fonts.

Only the popup's content region scrolls beneath the persistent header. Keep document-root and body scrolling disabled, but also keep the intrinsic size request within Chromium's 600 px height limit: native autosizing forces an outer scrollbar for oversized documents regardless of CSS overflow. The previous 700 px design target cannot be granted by a Chromium toolbar popup.

The design-system effort has two implementation issues: shared components and an isolated interactive development gallery, then production popup adoption with persisted appearance/colors and compatible backups. Both are implemented, and the user has approved the implementation. The temporary popup Components link, gallery entrypoint, and gallery-only fixtures have been removed; the actual popup is now the relevant UI surface in development and production. Detailed behavioral verification remains recorded in the issues.

Settings' approved visual hierarchy is Appearance (distinct theme selector), Playback (marker visibility and default marker color), and Backup (import/export). Prefer clear titles to redundant subtitles. Editor timestamps use a recessed panel with boxed adjustment controls; dialogs initially focus their title rather than the Close tooltip and retain crisp depth without blurred outer shadows or glow.

Keep All videos' repeated page heading and search label visually hidden while retaining accessible names; the search placeholder provides visible guidance. Separate the search bar from video cards by 16 px. Settings omits the informational marker-inheritance/implementation notice between Playback and Backup; actionable errors remain visible.

The This video summary card starts with the video title and bookmark count; do not repeat the This video navigation label inside the card.

Color controls show preset swatches and the native Custom picker without a separate hex-code readout. Keep accessible labels and the editor's Use default inheritance.

The [color wheel improvement](../.scratch/color-wheel-improvement/spec.md) is implemented locally, with user verification pending: Custom default-marker-color selection in Settings updates the picker locally and persists quietly after a pause in continuous changes. Do not show inline color-status text or intermediate success feedback while the wheel is open; show one toast on picker commit/close after the latest color is confirmed saved. Preset and remembered Custom selections save immediately, with success feedback after confirmation. Ordered writes preserve newer color, theme, and visibility choices. Native commit, leaving the picker, and popup navigation flush pending color work; videos-only transfer snapshots remain independent. Failures retain an explicitly unsaved preview and visible error rather than claiming success. Bookmark-editor colors remain draft-only until Save changes. Abrupt popup destruction before a commit/debounce boundary is not guaranteed to preserve an unsaved selection.

Use Tabler's outline React icons for functional controls and feedback. Bookmark menu actions, video actions, backup buttons, and theme choices pair icons with text. All videos uses a compact bookmark icon/count with a full accessible label; This video keeps an icon plus bookmark-count text. Action menus retain crisp depth without blurred outer shadows or glow.

Player-control polish is implemented locally, with user verification pending: quick add uses YouTube's control styling hook for alignment and an extension-owned rounded translucent pill shared with marker tooltips. Hover and keyboard focus reveal its label; save feedback temporarily occupies the same pill without shifting the control row. Shared styling increases contrast over bright content. See the [player-controls polish spec](../.scratch/player-controls-polish/spec.md).

## Import/export rewrite and launch versioning

The [import/export rewrite](../.scratch/import-export-rewrite/spec.md) is implemented locally, with source/runtime and release verification pending. It replaces the earlier settings-inclusive backup path; usage is documented in the README. The user requested no tests, builds, or commits for this implementation.

Both transfer selectors start with all available videos selected and offer case-insensitive partial-title filtering without changing selection or order. Select all includes hidden rows. Each selected video transfers all accepted bookmarks. Export reviews a fresh consistent snapshot of selected video IDs; selected-data changes require refreshed review and another final action, without automatically selecting newly added videos. Import rechecks relevant library data before committing and refreshes stale previews; preference-only changes do not invalidate review. Partial validation acceptance never permits partial persistence.

Transfer counts use plain bookmark labels, without “accepted”; validation omissions remain separately inspectable. Settings exposes one visible Import JSON action backed by a hidden native file input, not a duplicate Choose File row.

Import details for duplicates, metadata/title conflicts, and validation omissions retain separate outcome sections, with collapsed video groups inside each. Label groups with the incoming title, then the current stored title; use the ID or malformed record's file location only as a fallback. Group by video identity, not title text; disambiguate same-title videos with secondary IDs and keep ambiguous incoming records separate by file location. Show per-group item counts, chronological formatted timestamps, and inspectable reasons/values; state identical-duplicate handling once rather than on every timestamp. The [title-tree presentation](../.scratch/import-preview-title-tree/spec.md) does not change merge precedence, persisted metadata, or the wire schema, and does not fetch titles from YouTube.

Use one app-version source in package metadata and independent file-schema versioning. The launch target is app 1.0.0 with file schema 1 after the rewrite is verified and launch-ready, not during specification work. All prelaunch bookmarks/preferences and backups are disposable development data; no legacy import adapters, storage migrations, or preservation guarantees are required. Development backups using the old version field are unsupported, including version: 1; they are not the launch schemaVersion: 1 format. A development-data reset may occur at cutover, not as a side effect of normal postlaunch import/export. Patch releases carry compatible fixes, minor releases compatible features, and major releases breaking supported-contract changes. Import compatibility depends on the declared supported file schema, not whether the producing app is newer. Exact schema fields belong in the rewrite spec; no storage-key or format-identifier rename is required merely to start the launch schema at 1.

The earlier color-picker implementation's settings-inclusive backup coordination is historical. The rewrite must neither adopt imported preferences nor make videos-only transfer snapshots depend on saving the global default color. Normal picker commit/navigation persistence and honest settings-error feedback remain required.

## Boundaries and later ideas

First-version playback integration covers standard YouTube watch pages. Shorts, live streams, embeds, and `youtu.be` entry points are outside that integration. Use local extension storage via `wxt/utils/storage`; no account or cross-device sync. All videos has a partial-title filter; advanced sorting, fuzzy/typo-tolerant search, ID/bookmark-name search, and direct timestamp entry are deferred. No tags, playlists, thumbnail previews, keyboard shortcuts, timestamp precision mode, undo, or popup quick-add action. These are possible later ideas, not commitments. Welcome and Guide are deferred. Timeline-marker rendering remains a separate feature, not part of the design-system cutover.

## Project architecture

- Separate domain models, bookmark/storage logic, host-website messaging adapters, and thin WXT entrypoints. Popup, player markers, and backup features must use the same persisted model rather than creating independent stores.
- YouTube page integration has one thin host-level content entrypoint and one shared player lifecycle. Quick add and player-message handling consume the same navigation/media checks; keep feature UI separate from shared player operations. Popup-side active-tab discovery combines browser-tab classification with a content-side active-video snapshot. Separate execution contexts exchange typed messages rather than share live JavaScript state.
- Store each video and its bookmarks together as one authoritative video record. Derive video lists and bookmark counts from those records rather than maintaining separate indexes or counts.
- Route bookmark and preference mutations through the background worker. Serialize mutations for the same video so concurrent read-modify-write operations cannot overwrite each other's changes; coordinate whole-library imports and consistent backup snapshots with those mutations. A failed operation must not block subsequent ones.
- Use typed request/response messages with explicit success or failure results. Request validation returns a failure value; storage failures must also become failure responses, not successful feedback.
- Follow [coding conventions](agents/coding-style.md) for operation names, file ordering, helper placement, and execution-context terminology. Exact TypeScript fields, storage-key versions, and private implementation names belong in code.
